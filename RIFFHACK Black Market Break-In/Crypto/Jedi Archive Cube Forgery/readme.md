2. **Step 2**:

   This challenge involves RSA `e = 3` and lax PKCS#1 v1.5 signature verification. Normally, an RSA signature must be generated by a private key, but since the private key is not provided, we must forge one.

   Furthermore, the verifier in this challenge likely only checks the first few bytes of the decrypted block, failing to fully verify the PKCS#1 v1.5 format, the complete DigestInfo, and the full hash. This allows us to exploit the cube root of `e = 3` to forge a signature.

   First, calculate the SHA-256:

   ```python
   digest = hashlib.sha256(payload).digest()
   ```

   Then, calculate a fake prefix to deceive the verifier:

   ```python
   DI_SHA256 = bytes.fromhex("3031300d060960864801650304020105000420")

   prefix = b"\x00\x01\xff\x00" + DI_SHA256 + digest
   ```

3. **Step 3**:

   Using `e = 3`, we take the cube root of our block. We need to find a signature such that its cube results in high-order bytes that approximate our fake prefix.

   Since the RSA modulus for this challenge is 1024-bit, we must pad the fake prefix with 0s to a length of 128 bytes:

   ```python
   block = prefix + b"\x00" * (128 - len(prefix))
   ```

   Next, calculate:

   ```text
   s = ceil(cube_root(block))
   ```

   Because `e = 3`, the server calculates the following when verifying the signature:

   ```text
   s^3 mod n
   ```

   The signature obtained by rounding up the cube root will have a cube that approximates the block.

   Although the trailing bytes will differ due to rounding, the high-order prefix remains sufficiently intact to bypass the vulnerable verifier.
